# 指标口径说明

本文档定义电商用户行为数仓中所有核心指标的计算口径，确保 ADS 层对外输出的每一个指标都是可追溯、可复现、可解释的。

---

## 一、PV（Page View，页面浏览量）

**定义：**
用户每一次页面访问行为，计为一次 PV。

**计算公式：**
```sql
SELECT SUM(IF(behavior='pv', 1, 0)) AS pv
FROM dwd_user_behavior;
```

**口径说明：**
- 统计的是 `behavior='pv'` 的行为记录数，不去重。
- 同一个人在 1 分钟内点了 10 次页面，算 10 次 PV。
- 已过滤异常时间戳（约 1.5% 脏数据）。

**业务解释：**
PV 反映的是**页面整体的访问热度**，是流量大盘的基础指标。

---

## 二、UV（Unique Visitor，独立访客数）

**定义：**
在统计周期内，访问过页面的**去重用户数**。

**计算公式：**
```sql
SELECT COUNT(DISTINCT user_id) AS uv
FROM dwd_user_behavior
WHERE behavior = 'pv';
```

**口径说明：**
- 同一用户在同一天内访问 100 次，只算 1 个 UV。
- 统计粒度是「天」，跨天的同一用户在不同的分区里会各算一次。
- 用 `COUNT(DISTINCT user_id)` 实现去重。

**业务解释：**
UV 反映的是**真实覆盖了多少人**，与 PV 的比值（PV/UV）反映用户的活跃深度。

---

## 三、加购率（PV → Cart 转化率）

**定义：**
用户从「浏览页面」到「加入购物车」的转化比例。

**计算公式：**
```sql
ROUND(CAST(cart_cnt AS DOUBLE) / pv_cnt, 4)
```

**口径说明：**
- 分子：当天 `behavior='cart'` 的行为数
- 分母：当天 `behavior='pv'` 的行为数
- **先转 DOUBLE 再相除**：防止整数除法截断（比如 5/10 会变成 0）
- 保留 4 位小数，便于前端展示

**业务解释：**
加购率反映的是**商品对用户的吸引力**。加购率高，说明商品详情页、价格、活动吸引力强。

---

## 四、购买转化率（PV → Buy 转化率）

**定义：**
用户从「浏览页面」直接到「购买」的转化比例，是电商漏斗的最终环节。

**计算公式：**
```sql
ROUND(CAST(buy_cnt AS DOUBLE) / pv_cnt, 4)
```

**口径说明：**
- 分子：当天 `behavior='buy'` 的行为数
- 分母：当天 `behavior='pv'` 的行为数
- 全局转化率（整个统计周期）：约 **2.2%**，符合电商行业正常水平

**业务解释：**
购买转化率是**电商最核心的北极星指标**，反映整体运营效率。

---

## 五、复购率

**定义：**
在统计周期内，**购买天数 ≥ 2 天**的用户占总购买用户的比例。

**计算公式：**
```sql
SELECT
  COUNT(*) AS total_buyers,
  SUM(IF(buy_days >= 2, 1, 0)) AS repurchase_users,
  ROUND(CAST(SUM(IF(buy_days >= 2, 1, 0)) AS DOUBLE) / COUNT(*), 4) AS repurchase_rate
FROM (
  SELECT user_id, COUNT(DISTINCT dt) AS buy_days
  FROM dwd_user_behavior
  WHERE behavior = 'buy'
    AND dt != '2017-11-24'   -- 排除边界数据
  GROUP BY user_id
) t;
```

**口径说明（重要）：**

复购率有多种口径，本项目采用了经过调整后的严格口径：

| 口径 | 定义 | 优点 | 缺点 |
|---|---|---|---|
| 按购买次数 | 购买行为数 ≥ 2 | 简单 | 同一天点击两次购买按钮就算复购，容易虚高 |
| **按购买天数（本项目采用）** | 购买天数 ≥ 2 | 排除同日多次点击的干扰 | 需要 `COUNT(DISTINCT dt)` |
| 按订单号 | 不同 order_id ≥ 2 | 最贴近真实业务 | 原始数据无 order_id |

**本项目为什么选择「按购买天数」？**
1. 原始数据无 `order_id`，无法用订单号口径；
2. 首次按「购买次数」算出 64.98%，明显偏高，不符合业务常识；
3. 改用「购买天数」后算出 **53.68%**，更合理。

**为什么 53.68% 还是偏高？**
- 数据集只有 **9 天**（2017-11-25 ~ 2017-12-03），时间窗口短；
- 这个时间段是**双十二大促前夕**，用户购买频率天然偏高；
- 数据是**抽样样本**，无法代表整体大盘。

**如果生产环境做，会怎么做？**
1. 时间窗口拉长到 30 天或 90 天；
2. 用 `order_id` 去重，同一订单多件商品只算一单；
3. 定义更严格的复购：**跨月复购**（上月买过，本月又买）；
4. 区分品类复购率（快消品 vs 耐用品，复购定义不同）。

**业务解释：**
复购率衡量的是**用户忠诚度**，是电商 LTV（用户生命周期价值）的核心预测指标。

## 六、TopN 商品

**定义：**
每日**购买量（buy_cnt）**排名前 10 的商品。

**计算公式：**
```sql
SELECT dt, item_id, buy_cnt, rank
FROM (
  SELECT
    dt, item_id, buy_cnt,
    ROW_NUMBER() OVER (PARTITION BY dt ORDER BY buy_cnt DESC) AS rank
  FROM dws_item_daily
  WHERE buy_cnt > 0
) t
WHERE rank <= 10;
```

**口径说明：**
- 用 `PARTITION BY dt` 按天分组，每天各自算 TopN；
- 用 `ROW_NUMBER()` 排序（并列时会强制分出不同名次）；
- 外层过滤 `buy_cnt > 0`，减少排序数据量；
- 如果业务要求**并列名次相同**，改用 `DENSE_RANK()`。

**业务解释：**
TopN 反映的是**爆款商品**，可以用于运营决策（备货、推广、活动选品）。

## 七、GMV（成交总额）—— 替代说明

**定义（标准）：**
GMV = 成交订单的总金额，是电商最核心的营收指标。

**本项目为什么无法直接算 GMV？**
原始数据集 **没有价格字段**，只有：
- user_id, item_id, category_id, behavior, timestamp

**本项目的替代方案：**
- 用 `buy_cnt`（购买量）作为 GMV 的**代理指标**；
- 在可视化中标注为「购买量」，不标注为「GMV」，避免误导；
- 在 README 和面试中主动说明：「原始数据无价格字段，GMV 需要补一张价格维表才能计算」。

**如果生产环境要做，会怎么做？**
1. 补一张 `dim_item_price(item_id, price)` 商品价格维表；
2. GMV 计算：
```sql
SELECT SUM(p.price) AS gmv
FROM dwd_user_behavior d
JOIN dim_item_price p ON d.item_id = p.item_id
WHERE d.behavior = 'buy';
```
3. 注意 GMV 通常要**剔除退款订单**，需要退款状态字段。

## 八、指标口径汇总表

| 指标 | 计算公式 | 统计粒度 | 关键口径 |
|---|---|---|---|
| PV | SUM(IF(behavior='pv', 1, 0)) | 按天 | 不去重 |
| UV | COUNT(DISTINCT user_id) | 按天 | 按 user_id 去重 |
| 加购率 | cart_cnt / pv_cnt | 按天 | 转 DOUBLE 再相除 |
| 购买转化率 | buy_cnt / pv_cnt | 按天 | 转 DOUBLE 再相除 |
| 复购率 | SUM(IF(buy_days>=2,1,0)) / COUNT(*) | 全周期 | 按购买天数去重 |
| TopN | ROW_NUMBER() OVER (PARTITION BY dt ORDER BY buy_cnt DESC) | 按天 | 取 rank <= 10 |
| GMV | 本项目以 buy_cnt 替代 | - | 原始数据无价格字段 |

---

## 九、口径设计原则总结

1. **先探查再定义**：所有口径在数据探查阶段确认，写进文档后才开始建表。
2. **分母不能为 0**：所有比率类指标都加 `WHERE pv_cnt > 0` 防御。
3. **精度先转 DOUBLE**：所有整数相除的比率都要先 `CAST AS DOUBLE`。
4. **数据边界要处理**：`dt='2017-11-24'` 是时区边界产生的半天数据，做复购率等全周期指标时排除。
